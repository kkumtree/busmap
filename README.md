# 전주 버스맵 · 나의 환승지

OSM 기반의 선택형 이름 레이어 지도와 세 탭으로 구성한 GitHub Pages용 정적 웹앱입니다.

```sh
npm ci
npm start
```

<http://127.0.0.1:8000>에서 엽니다. 키는 화면에서 입력하고 기본적으로 메모리에만 보관합니다(원하는 경우에만 브라우저 저장소 저장을 선택). 페이지를 열거나 탭을 바꾸는 것만으로 버스 API를 호출하지 않습니다. 지도 타일은 OpenFreeMap에서 별도로 불러옵니다.

## 디자인 시스템과 모바일

[Backward UI](https://github.com/kkumtree/freewrite-ui-kit)의 `portal-cream` 테마·`--bw-*` 토큰을 사용합니다. 공유 CSS는 `design-system/bw.css`, 버전·원본 커밋·해시는 `design-system/source.json`에 있습니다. 앱 고유 배치는 `style.css`가 담당하며 Pretendard를 사용합니다.

```sh
node scripts/sync-design-system.mjs ../freewrite-ui-kit
```

휴대폰 상단에는 세 작업 탭과 **지도 크게 / 경로 보기** 버튼이 있습니다. **메뉴**에서 작업 화면을 전환하거나 정류장을 불러올 수 있습니다. **API 키** 창에는 이번 페이지의 서비스별 호출 횟수가 표시됩니다. 작업 패널을 스크롤하는 동안 현재 탭 제목이 상단에 남습니다.

지도 오른쪽 위에는 **확대 · 축소**, **레이어** 순서로 버튼을 가로 배치합니다. 지도 맨 아래에는 제공자의 저작권 링크를 두고, 현재 위치 버튼은 그 위에 배치합니다. 화면이 좁으면 출처 문구가 두 줄로 표시됩니다. 화면이 낮아지면 지도와 편집 영역을 하나씩 열 수 있습니다.

## 1. 환승지 지정

- 환승지 하나를 지정합니다.
- 1구간은 **여러 출발지 → 환승지 하나**, 2구간은 **환승지 하나 → 여러 도착지**입니다.
- 출발지·도착지마다 노선을 여러 개 체크해 저장합니다. 서로 다른 정류장의 노선 선택은 섞이지 않습니다.
- 지도, 검색, 정류장번호 직접 입력으로 정류장을 추가합니다. 좌표가 없는 직접 입력 정류장은 지도에 표시하지 않습니다.
- 출발지 목록 → 환승지 카드 → 도착지 목록을 세로로 표시합니다. 각 정류장을 누르면 해당 구간의 노선을 선택하며, 항목 수가 늘어나도 겹치지 않습니다.
- **새 직행**에서는 출발지와 도착지를 고르고 한 구간의 노선을 저장합니다. 저장한 직행의 도착정보는 출발지만 조회합니다. **새 환승**에서는 환승지를 지정하고 두 구간의 노선을 각각 저장합니다.
- **후보 노선 조회**는 승강장 서비스의 `/general_busstop_common`으로 선택한 두 정류장의 전체 경유 노선을 조회하고, 공통 노선 ID에 대해서만 경유 정류장 순서를 확인합니다. 실시간 도착정보와 환승 검색 결과는 후보 결정에 사용하지 않습니다. 표준ID가 없으면 최근 24시간 경유 기록에서 번호·이름에 일치하는 고유 ID를 먼저 찾고, 없을 때만 `/bus_location2_stopno_common`에 정류장번호를 보냅니다. 승강장 서비스가 503을 반환하면 각 구간에서 전에 확인한 노선 ID만 대상으로 경유 순서를 확인합니다(최대 4개). 사용자가 지정한 양 끝의 번호·이름·표준ID와 진행 순서를 검증한 일부 후보만 표시합니다. 이 확인까지 실패하면 두 서비스의 오류를 표시하고 중단합니다. 서비스 연결 실패(HTTP 503 또는 제공기관 코드 05) 직후 1분 동안 같은 기능은 다시 호출하지 않으며, 시간이 지나도 자동 호출하지 않습니다. 미저장 형상은 같은 버튼에서 추가 조회하고 오류 시 자동 재시도하지 않습니다. 전체 노선 목록을 준비하는 단계는 없습니다.
- 이름을 붙여 **경로 묶음 저장**을 누릅니다. 각 출발지·도착지에서 한 개 이상의 노선을 선택해야 저장할 수 있습니다.

## 2. 저장한 경로

목록을 여는 동작은 로컬 데이터만 읽습니다. **도착정보 조회**를 눌렀을 때만 출발지들과 환승지의 도착정보를 각각 한 번 요청하고, 저장한 노선만 필터링합니다. 도착지는 조회하지 않습니다. 동일 정류장은 중복 조회하지 않습니다. 표준ID가 없는 직접 입력 정류장은 이 수동 조회 때만 ID를 확인하는 추가 요청이 필요합니다.

편집 버튼은 네트워크 요청 없이 묶음을 불러옵니다. 같은 묶음을 편집해 저장하면 기존 항목을 갱신합니다. 삭제·되돌리기를 제공합니다. 이전 버전의 단일 직행·환승 경로도 원래 저장키를 건드리지 않고 별도 읽기 목록에 유지합니다.

## 3. 환승정보 서비스

출발지 하나와 도착지 하나를 지정하고 **환승정보 조회**를 눌러 서비스가 제안하는 경로를 표시합니다. 사용자 지정 환승지 묶음과 별도 기능입니다. 조회 버튼을 누를 때만 요청하며 자동 갱신·재시도하지 않습니다. 경로의 시간·거리 단위는 명세에 명시되어 있지 않아 API 원문값으로 표시합니다.

## 지역 분리

지역별 설정은 `regions/`에 모아 두었습니다. `regions/jeonju.js`가 지도 초기 시점·확대 수준, 좌표 범위, 이름 라벨 데이터, 출처 표기를 담고, `regions/index.js`가 지역 목록과 기본 지역, `regionById()`·`inRegion()`·`applyRegion()`을 제공합니다. 다른 지역을 추가할 때는 같은 형식으로 파일을 하나 만들고 `REGIONS` 배열에 넣으면 되며, 첫 항목이 기본 지역입니다. 지금은 지역 이름·지도 시점·좌표 범위만 이 설정에서 읽고, 상단 지역 탭은 아직 없습니다.

## 정류장 구분 정보

이름 옆에 정류장번호를 표시합니다. 확보된 방면·주소가 있으면 우선 사용하고, 없으면 이미 보관 중인 노선 정류장 순서의 다음 정류장 이름을 표시합니다. 추가 정보가 없으면 **방면 미확인**으로 표시합니다. 좌표값은 화면에 표시하지 않고 지도 내부 처리와 저장에만 사용합니다. 번호로 방면을 추측하거나 구분 정보를 얻기 위해 자동 호출하지 않습니다.

화면의 `About → 활용 API` 탭에 위 다섯 데이터와 배경지도의 호출 시점을 함께 표시합니다.

정류장 목록은 ‘정류장 불러오기’로만 갱신합니다. 후보·도착·환승 조회에서 표준ID와 최근 경유 기록이 없으면 승강장 서비스의 `/bus_location2_stopno_common`으로 필요한 정류장만 확인합니다. 과거 정류장 파일의 ID를 사용하는 실행 경로는 제거했습니다. 정류장번호·이름과, 좌표가 제공되면 150m 이내인지 검증합니다. 이름이나 번호만 비슷한 정류장을 임의로 합치지 않습니다.

저장키:

- `busmap.transfer-plans.v1`: 환승지, 여러 출발지·도착지와 각 정류장의 선택 노선들
- `busmap.stops.v1`: 수동으로 받은 정류장 목록
- `busmap.route-stops.v2`: 노선 ID별 메타데이터·정류장 순서(기존 저장 데이터를 재사용)
- `busmap.apikeys.v1`: 브라우저에 저장에 동의한 경우에만 API 키(선택)
- `busmap.journeys.v1`: 이전 버전 데이터, 유지

API 키는 경로·정류장 저장 데이터에 포함하지 않습니다. 기본은 이 탭의 메모리에만 있고 새로고침하면 사라집니다. API 키 창에서 **브라우저에 저장**을 켜면 5초 뒤에 동의 버튼이 열리고, 동의했을 때만 `busmap.apikeys.v1`에 남습니다. 저장된 키가 있으면 새 탭에서 한 번 안내 카드를 표시합니다. **확인**으로 닫거나 **API 키 설정**으로 바로 이동할 수 있습니다. 공용 PC에서는 끄고 쓰세요. 화면에서도 이미 적용한 키는 앞 4자리와 뒤 4자리만 마스킹해 표시하고, 입력창은 비워 두어 적용된 키가 다시 전송되지 않습니다. 로컬 저장은 같은 브라우저·주소에서 유지하며 기기 간 동기화는 하지 않습니다. `.env`는 Git과 정적 배포에서 제외되고 개발 서버도 제공하지 않습니다. `.env`의 키를 사용하는 진단 명령은 일일 한도를 고려해 필요할 때만 실행하세요.

## 검증과 배포

```sh
npm test
```

XML·키 처리, 후보 범위 조회, 여러 출발·도착 정류장별 노선 저장, 체크 해제 제외, 저장 복원, 출발지·환승지만 도착 조회 대상으로 선택하는 로직, 메타데이터 표시, 지도 컨테이너 크기와 패딩을 테스트합니다.

`python3 test/serve-fixtures.py`는 <http://127.0.0.1:8001>에서 가상 데이터로 UI를 검증하는 개발 전용 서버입니다. 실제 공공데이터 API를 호출하지 않습니다. 배포에 포함되지 않습니다.

세 탭 개편은 추가 실제 버스 API 호출 없이 로컬 테스트와 화면 검증으로 확인했습니다. 실서비스 종단 검증은 아직 하지 않았습니다. 이전 응답에서 30887→30920은 61번(순번 22→32), 30920→36351은 74·75번(순번 10→20)이 확인됐으며, 이후 일부 실시간·환승 요청에서 제공기관 연결실패가 발생했습니다.

GitHub Settings → Pages → Source를 GitHub Actions로 선택하고 main에 push하면 테스트 후 정적 파일이 배포됩니다. GitHub Actions에서 배포 상태를 확인할 수 있습니다.

배경지도는 [OpenFreeMap Positron](https://openfreemap.org/quick_start/)에서 symbol 레이어를 제외한 스타일입니다. OpenFreeMap / OpenMapTiles / OpenStreetMap 출처 표기를 유지합니다. 버스 데이터: 전주시 / 공공데이터포털, 출처표시 제1유형. MapLibre 라이선스는 vendor에 포함됩니다.

## 환승 경로 목록과 선형 보관

출발지 목록 → 환승지 한 곳 → 도착지 목록을 세로로 배치합니다. 정류장과 선택한 노선 번호를 행별로 표시하며 개수가 늘어나도 겹치지 않습니다. 선택한 행의 노선 체크 목록만 아래에 펼칩니다. 저장 목록의 경로 펼치기도 로컬 동작이며 도착정보 조회와 분리되어 있습니다. 전체 정류장 묶음은 검색 영역을 펼쳤을 때만 표시합니다.

`후보 노선 조회`는 `/bus_stop_drawing_common`에 확인된 노선 ID, 승하차 표준ID, `sStdId4=1`을 보내 해당 단일 승차 구간의 형상을 받습니다. 환승 전·후도 각각 독립적인 직행 구간으로 조회합니다. 전체 노선 형상을 새로 받거나 실패 시 다른 API·파라미터로 재시도하지 않습니다.

반환된 링크별 꼭짓점과 순서를 보존하고, 로컬 목록에서 찾은 중간 정류장 위치·순서로 선택 구간을 검증합니다. 도로 조각 사이의 빈 공간은 직선으로 잇지 않고 `MultiLineString`으로 표시합니다. 위치 이탈·큰 누락·복수 후보·중간 정류장 불일치를 구분해 저장합니다. 알 수 없는 좌표계는 추측해서 변환하지 않습니다.

구간별 캐시는 서비스·노선 ID·승하차 표준ID·구분·순번으로 구분합니다. 원본의 공개 형상 필드, 요청 조합, 파서 버전, 조회 시각을 IndexedDB에 보관합니다. 저장 경로에는 구간 선형·출처·진단 정보도 저장하므로 펼치기와 선택만으로 재호출하지 않습니다. 기존 저장 선형과 노선 ID 기반의 과거 캐시는 그대로 읽을 수 있습니다.

`test/fixtures/101-section.json`은 101번 `30920 → 36347`에서 한 번 받은 실제 구간 형상 응답의 공개 필드입니다. HTTP 200, 꼭짓점 90개, 링크 16개를 수신했고 중간 정류장 6곳으로 진행 순서를 검증했습니다. 기존 전체 형상 클리핑 방식은 같은 응답을 연결 미확정으로 거절하지만, 새 방식은 링크 사이 최대 27.1m의 틈을 그리지 않고 구간을 표시합니다. 이 한 구간 검증을 다른 모든 노선의 성공으로 일반화하지 않습니다. 재생 화면은 `python3 test/serve-fixtures.py --recorded-101`로 확인하며, 이 서버의 API는 전부 로컬 응답입니다.

페이지를 열 때 미리 채워지는 경로는 없습니다. 초기 화면의 출발지·환승지·도착지는 비어 있으며, 저장한 묶음을 직접 열거나 편집할 때만 정류장이 채워집니다. 탭을 바꾸거나 새 묶음을 시작하면 검색창·정류장번호 입력도 비웁니다. `data/focus-network.json`은 초기 조사 시점의 키 없는 수집 이력으로, 앱이 읽지 않으며 Pages 산출물에도 포함하지 않습니다.

## 장소별 레이어와 정류장 묶음

정류장 선택을 열었을 때, 축소 지도는 인접 정류장을 숫자로 묶고 클릭하면 해당 일대로 확대합니다. 14레벨부터 개별 정류장을 표시하되 아이콘 중첩을 허용하지 않습니다. 이 묶음은 MapLibre의 공간 클러스터이며 법정동 경계별 집계가 아닙니다. 정류장 목록은 기존 수동 로드 데이터를 재사용하므로 지도 확대·클릭은 버스 API를 호출하지 않습니다.

- **법정동**: 기존 `data/dong-labels.geojson`의 17개 이름을 11~15.5레벨에 표시합니다. OSM 지명을 전주시 법정동 명칭과 대조한 이름 표시용 위치로, 공식 경계나 전체 법정동 목록이 아닙니다. 클릭하면 해당 일대로 확대합니다.
- **장소별 레이어**: OpenFreeMap의 OpenMapTiles `place`와 `poi`를 직접 표시합니다. 동네·생활권(`quarter`, `neighbourhood` 등)은 14레벨부터, 학교·대학 / 공공시설 / 철도역 / 버스터미널 / 의료시설 / 공원은 각각 독립 체크박스로 13레벨부터 타일의 `class`·`subclass`·`rank`와 확대 수준으로 밀도를 제한합니다. 장소 이름을 클릭하면 확대합니다. 도로명과 일반 상점명은 표시하지 않습니다.
- 정적 아파트 추출 목록은 더 이상 지도에서 읽지 않습니다. 네이티브 타일에 단지 이름이 없으면 표시되지 않으며, `poi`에는 모든 아파트나 KTX 정차 여부를 보장하는 공통 depth가 없습니다.
- OSM의 `place` 분류는 한국의 법정동·행정동과 일대일로 대응하지 않습니다. 법정동별 정확한 집계에는 별도 공식 경계 자료가 필요합니다.

출처: OpenStreetMap 기여자 / OpenMapTiles / OpenFreeMap. 별도 OSM 파싱이나 Overpass 호출 없이 화면에 필요한 벡터 타일을 사용합니다. 기존 정적 이름 자료의 출처·라이선스는 각 파일에 보존합니다.

오른쪽 아래 현재 위치 버튼은 MapLibre GeolocateControl을 사용합니다. 버튼을 눌렀을 때만 브라우저 위치 권한으로 지도를 이동하며 위치를 저장하지 않습니다. HTTPS 또는 localhost에서 사용할 수 있고 권한 거부·시간 초과 시 안내합니다. 실제 위치 수신은 개발 검증에서 실행하지 않습니다.

## GitHub Pages 운영

배포 주소: <https://kkumtree.github.io/busmap/>. GitHub Pages의 Source는 GitHub Actions로 설정되어 있습니다. `main`에 push하면 `Deploy GitHub Pages`가 테스트 → 공개 정적 파일 패키징 → 배포를 실행합니다. GitHub 설정의 **Pages → Source는 GitHub Actions**로 둡니다. 배포에 API 키나 Actions Secrets는 필요하지 않으며, 방문자가 페이지에서 자신의 키를 입력합니다.

Pages 산출물은 공개 파일 목록만 복사합니다. `.env`, 진단 스크립트, 원본 수집 이력, 테스트와 node_modules는 배포하지 않습니다. 로컬 저장과 IndexedDB는 사이트 주소별로 분리되므로 localhost에서 저장한 경로가 GitHub Pages 주소로 자동 이동하지는 않습니다.

2026-11-01 최초 배포 성공: [Deploy GitHub Pages 실행 기록](https://github.com/kkumtree/busmap/actions/runs/41304744468). 테스트 23개와 배포 주소의 HTML·JS·지도 자료 응답, `.env` 비공개(404)를 확인했습니다.

선형이 없을 때는 노선별로 미조회, 요청 실패(제공기관 오류 문구), 응답 없음, 좌표계 확인 필요, 구간 연결 미확정, 정류장 순서 미확인을 구분합니다. 오류 사유는 경로 묶음과 함께 저장합니다. 이전 버전의 미확보 기록에는 원인이 없을 수 있으므로 실제 API 오류로 단정하지 않고 ‘원인 미기록’으로 표시합니다. 상태 표시·경로 펼치기 자체는 추가 API를 호출하지 않습니다.

현재 UI 글꼴은 Pretendard Variable입니다. API 키 창의 호출 카운터는 서비스별 한 행의 숫자로 표시하며 페이지 메모리에만 유지합니다. 대량 노선 매핑 준비 기능은 제거했으며, 승강장 서비스(15158979)를 다섯 번째 API로 추가했습니다. 승강장용 서비스별 키 입력과 다섯 번째 세션 호출 카운터를 제공합니다.
