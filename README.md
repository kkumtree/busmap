# 전주 버스맵 · 나의 환승지

OSM 기반의 라벨 없는 지도와 세 탭으로 구성한 GitHub Pages용 정적 웹앱입니다.

```sh
npm ci
npm start
```

<http://127.0.0.1:8000>에서 엽니다. 키는 화면에서 입력하고 메모리에만 보관합니다. 페이지를 열거나 탭을 바꾸는 것만으로 버스 API를 호출하지 않습니다. 지도 타일은 OpenFreeMap에서 별도로 불러옵니다.

## 1. 환승지 지정

- 환승지 하나를 지정합니다.
- 1구간은 **여러 출발지 → 환승지 하나**, 2구간은 **환승지 하나 → 여러 도착지**입니다.
- 출발지·도착지마다 노선을 여러 개 체크해 저장합니다. 서로 다른 정류장의 노선 선택은 섞이지 않습니다.
- 지도, 검색, 정류장번호 직접 입력으로 정류장을 추가합니다. 좌표가 없는 직접 입력 정류장은 지도에 표시하지 않습니다.
- **후보 노선 조회**를 눌렀을 때만 선택한 구간을 조회합니다. 전체 노선을 수집하지 않고 도착정보·환승 검색에서 얻은 후보의 정류장 순서만 확인합니다. 모든 노선이 포함된 결과는 아닙니다. 자동 재시도하지 않습니다.
- 이름을 붙여 **경로 묶음 저장**을 누릅니다. 각 출발지·도착지에서 한 개 이상의 노선을 선택해야 저장할 수 있습니다.

## 2. 저장한 경로

목록을 여는 동작은 로컬 데이터만 읽습니다. **도착정보 조회**를 눌렀을 때만 출발지들과 환승지의 도착정보를 각각 한 번 요청하고, 저장한 노선만 필터링합니다. 도착지는 조회하지 않습니다. 동일 정류장은 중복 조회하지 않습니다. 표준ID가 없는 직접 입력 정류장은 이 수동 조회 때만 ID를 확인하는 추가 요청이 필요합니다.

편집 버튼은 네트워크 요청 없이 묶음을 불러옵니다. 같은 묶음을 편집해 저장하면 기존 항목을 갱신합니다. 삭제·되돌리기를 제공합니다. 이전 버전의 단일 직행·환승 경로도 원래 저장키를 건드리지 않고 별도 읽기 목록에 유지합니다.

## 3. 환승정보 서비스

출발지 하나와 도착지 하나를 지정하고 **환승정보 조회**를 눌러 서비스가 제안하는 경로를 표시합니다. 사용자 지정 환승지 묶음과 별도 기능입니다. 조회 버튼을 누를 때만 요청하며 자동 갱신·재시도하지 않습니다. 경로의 시간·거리 단위는 명세에 명시되어 있지 않아 API 원문값으로 표시합니다.

## 정류장 구분 정보

이름 옆에 정류장번호를 표시합니다. 확보된 방면·주소가 있으면 우선 사용하고, 없으면 이미 보관 중인 노선 정류장 순서의 다음 정류장 이름을 표시합니다. 추가 정보가 없으면 **방면 미확인**으로 표시합니다. 좌표값은 화면에 표시하지 않고 지도 내부 처리와 저장에만 사용합니다. 번호로 방면을 추측하거나 구분 정보를 얻기 위해 자동 호출하지 않습니다.

## 데이터·키·저장

| 데이터 | 용도 |
| --- | --- |
| [정류장 15080859](https://www.data.go.kr/data/15080859/fileData.do) | 수동 로드 시 공식 Swagger의 최신 날짜 버전 선택, JSON 전체 페이지 조회 |
| [노선 15159001](https://www.data.go.kr/data/15159001/openapi.do) | 후보 노선의 경유 순서 확인 |
| [도착정보 15159002](https://www.data.go.kr/data/15159002/openapi.do) | 출발지·환승지의 수동 도착 조회, 후보 노선 파악 |
| [환승정보 15159000](https://www.data.go.kr/data/15159000/openapi.do) | 출발·도착 경로 조회, 후보 노선 파악 |

화면의 `About → 활용 API` 탭에 위 네 데이터와 배경지도의 호출 시점을 함께 표시합니다.

정류장 데이터는 ‘정류장 불러오기’로만 갱신하고 이후 로컬 목록을 사용합니다. 표준ID가 없는 경우 같은 데이터셋의 ID 필드가 있는 버전(현재 2024년)을 정류장번호 조건으로 최대 5건만 조회하고 좌표가 150m 이내인지 확인합니다. TAGO JUB 식별자는 후보 조회에만 사용하며, 실제 경유 여부는 최신 정류장번호·이름으로 다시 대조합니다.

저장키:

- `busmap.transfer-plans.v1`: 환승지, 여러 출발지·도착지와 각 정류장의 선택 노선들
- `busmap.stops.v1`: 수동으로 받은 정류장 목록
- `busmap.route-stops.v2`: 조회한 후보 노선의 정류장 순서(하루 재사용)
- `busmap.journeys.v1`: 이전 버전 데이터, 유지

API 키는 저장 데이터에 포함하지 않습니다. 화면에서도 이미 적용한 키는 앞 4자리와 뒤 4자리만 마스킹해 표시하고, 입력창은 비워 두어 적용된 키가 다시 전송되지 않습니다. 로컬 저장은 같은 브라우저·주소에서 유지하며 기기 간 동기화는 하지 않습니다. `.env`는 Git과 정적 배포에서 제외되고 개발 서버도 제공하지 않습니다. `.env`의 키를 사용하는 진단 명령은 일일 한도를 고려해 필요할 때만 실행하세요.

## 검증과 배포

```sh
npm test
```

XML·키 처리, 후보 범위 조회, 여러 출발·도착 정류장별 노선 저장, 체크 해제 제외, 저장 복원, 출발지·환승지만 도착 조회 대상으로 선택하는 로직, 메타데이터 표시를 테스트합니다.

`python3 test/serve-fixtures.py`는 <http://127.0.0.1:8001>에서 가상 데이터로 UI를 검증하는 개발 전용 서버입니다. 실제 공공데이터 API를 호출하지 않습니다. 배포에 포함되지 않습니다.

세 탭 개편은 추가 실제 버스 API 호출 없이 로컬 테스트와 화면 검증으로 확인했습니다. 실서비스 종단 검증은 아직 하지 않았습니다. 이전 응답에서 30887→30920은 61번(순번 22→32), 30920→36351은 74·75번(순번 10→20)이 확인됐으며, 이후 일부 실시간·환승 요청에서 제공기관 연결실패가 발생했습니다.

GitHub Settings → Pages → Source를 GitHub Actions로 선택하고 main에 push하면 테스트 후 정적 파일이 배포됩니다. GitHub Actions에서 배포 상태를 확인할 수 있습니다.

배경지도는 [OpenFreeMap Positron](https://openfreemap.org/quick_start/)에서 symbol 레이어를 제외한 스타일입니다. OpenFreeMap / OpenMapTiles / OpenStreetMap 출처 표기를 유지합니다. 버스 데이터: 전주시 / 공공데이터포털, 출처표시 제1유형. MapLibre 라이선스는 vendor에 포함됩니다.

## 환승지 연결도와 선형 보관

환승지를 중심으로 출발지는 왼쪽, 도착지는 오른쪽에 고정합니다. 정류장 또는 연결선을 선택했을 때 해당 가지의 노선 체크 목록만 펼칩니다. 저장 목록에서도 연결도 펼치기는 로컬 동작이며 도착정보 조회와 분리되어 있습니다. 전체 정류장 점은 검색 영역을 펼쳤을 때만 표시합니다.

`후보 노선 조회`에서만 `/bus_nosun_drawing_common`을 요청하고, 동일 노선ID의 형상은 IndexedDB `busmap-shapes`에 보관해 재사용합니다. 원본 링크별 점 순서를 유지하며 끊긴 링크 사이를 임의로 연결하지 않습니다. 확인된 WGS84 좌표이고 승차·하차 정류장의 순서와 위치를 유일하게 연결할 수 있을 때만 구간을 잘라 표시합니다. 알 수 없는 좌표계·왕복/순환 중복·연결 누락이면 표시를 보류합니다.

경로 묶음에는 선택 구간의 좌표와 형상 참조도 함께 저장합니다. 저장 경로 펼치기·구간 선택·노선 체크에는 형상 API를 호출하지 않습니다. 이 구현은 합성 데이터로 구간 자르기·모호한 경로 거부·동시 요청 중복 방지·저장 복원을 검증했습니다. 실제 제공기관 응답 형식에 대한 검증은 아래 연결 오류로 완료하지 못했습니다.

이번 제한 검증에서 버스 API는 **4회**만 호출했습니다. 30927·36347 정류장은 수신했고, 61번 노선 정류장 1회와 형상 1회는 `서비스 연결실패`를 반환했습니다. 추가 요청이나 재시도는 하지 않았습니다. 범위는 사용자 지정 30887/30927 → 30920 → 36347/36351, 노선 61/200/101/74/75로 제한했습니다. 해당 구간 조회에서는 지정하지 않은 번호의 후보 노선 정류장까지 확장하지 않습니다.

페이지를 열 때 미리 채워지는 경로는 없습니다. 초기 화면의 출발지·환승지·도착지는 비어 있으며, 저장한 묶음을 직접 열거나 편집할 때만 정류장이 채워집니다. 탭을 바꾸거나 새 묶음을 시작하면 검색창·정류장번호 입력도 비웁니다. `data/focus-network.json`은 초기 조사 시점의 키 없는 수집 이력으로, 앱이 읽지 않으며 Pages 산출물에도 포함하지 않습니다.

## 동 이름·아파트 이름 레이어

도로명·상점·일반 시설 라벨은 표시하지 않습니다. 동 이름은 11레벨부터, 단지명은 14레벨부터 표시하고 각각 끌 수 있습니다. 좌표값은 UI에 표시하지 않습니다.

- `data/dong-labels.geojson`: OpenFreeMap/OpenMapTiles의 OSM 지명 중 [전주시 법정동 명칭](https://edu.jeonju.go.kr/index.9is?contentUid=9be517a74f8dee91014f9211968310c9)과 대조한 17개 이름. **법정동 경계 데이터가 아닌 이름 표시용 위치**입니다.
- `data/apartment-labels.geojson`: 전주 서부 제한 영역의 OSM named residential area에서 추출한 57개 단지명. 개별 101동·102동 같은 건물 번호는 제외합니다. 전주시 전체 단지를 포괄하는 자료는 아닙니다.
- 출처: OpenStreetMap 기여자 / OpenMapTiles / OpenFreeMap. 추출 데이터는 ODbL 조건을 따르며, 각 파일에 출처·라이선스를 기록합니다. 배경지도 출처 표시도 유지합니다.

이름 자료는 정적 파일로 배포하며, 사용자가 지도를 움직일 때 별도의 공공데이터 API를 호출하지 않습니다. 추출 도구는 `scripts/build-map-labels.py`와 `scripts/build-dong-labels.mjs`이며 자동 빌드에서는 실행하지 않습니다.

## GitHub Pages 운영

배포 주소: <https://kkumtree.github.io/busmap/>. GitHub Pages의 Source는 GitHub Actions로 설정되어 있습니다. `main`에 push하면 `Deploy GitHub Pages`가 테스트 → 공개 정적 파일 패키징 → 배포를 실행합니다. GitHub 설정의 **Pages → Source는 GitHub Actions**로 둡니다. 배포에 API 키나 Actions Secrets는 필요하지 않으며, 방문자가 페이지에서 자신의 키를 입력합니다.

Pages 산출물은 공개 파일 목록만 복사합니다. `.env`, 진단 스크립트, 원본 수집 이력, 테스트와 node_modules는 배포하지 않습니다. 로컬 저장과 IndexedDB는 사이트 주소별로 분리되므로 localhost에서 저장한 경로가 GitHub Pages 주소로 자동 이동하지는 않습니다.

2026-11-01 최초 배포 성공: [Deploy GitHub Pages 실행 기록](https://github.com/kkumtree/busmap/actions/runs/41304744468). 테스트 23개와 배포 주소의 HTML·JS·지도 자료 응답, `.env` 비공개(404)를 확인했습니다.

선형이 없을 때는 노선별로 미조회, 요청 실패(제공기관 오류 문구), 응답 없음, 좌표계 확인 필요, 구간 연결 미확정, 정류장 순서 미확인을 구분합니다. 오류 사유는 경로 묶음과 함께 저장합니다. 이전 버전의 미확보 기록에는 원인이 없을 수 있으므로 실제 API 오류로 단정하지 않고 ‘원인 미기록’으로 표시합니다. 상태 표시·경로 펼치기 자체는 추가 API를 호출하지 않습니다.
